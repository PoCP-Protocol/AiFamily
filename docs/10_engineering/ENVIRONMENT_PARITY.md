# 测试环境与生产环境功能等价规范

## 1. 强制原则

AiFamily 的开发、测试、生产三个环境必须是**功能完整、彼此行为等价**的环境。环境之间允许数据和外部依赖不同，但不允许业务能力被阉割、路由被隐藏、状态机被简化、权限/同意/审计被绕过，或把“开发态假数据”当成另一套产品。

```text
开发环境 = 测试环境 = 生产功能 + 各自适配的数据/外部依赖
开发/测试环境 ≠ 生产功能的简化版
```

该原则适用于 34 个 UI、所有业务场景、Domain、API、Workflow、AI Runtime、服务协作和商业流程。生产准入是数据和供应商准入，不是补做缺失功能。

## 2. 必须相同的内容

测试环境和生产环境必须使用相同的：

- 路由与 API 契约（包括成功、拒绝、超时、幂等和错误语义）；
- Domain 聚合、业务规则、状态机、Named Action 和事件；
- 身份、租户、家庭权限、Consent、未成年人保护和审计规则；
- 数据边界、Fact/Perspective/Recommendation/Action/Outcome 语义；
- Workflow 的触发条件、重试、补偿、阶段推进和人工闸门；
- AI Runtime 的输入输出契约、来源、版本、解释、限制和人工确认要求；
- 服务案件、任务、验收、质量、贡献和争议规则；
- 商品、订单、权益、退款和续购的业务规则（支付可使用沙箱）；
- 前端 UI 的可用功能路径和可见状态（数据内容可以是 fixture）。

## 3. 允许不同的内容

仅允许替换环境适配器，不允许替换业务规则：

- 数据库实例、租户和家庭数据集；
- AI/支付/短信/邮件等外部供应商为可审计的 sandbox、stub 或 deterministic adapter；
- 密钥、域名、并发规模、资源配额和日志采样率；
- 时间、队列和故障注入控制器；
- 测试夹具的生成方式和数据清理策略。

所有模拟数据必须标记 `data_class=SYNTHETIC`，且只能通过与生产实现相同的 Port/Adapter 接口注入。模拟适配器不得改变状态迁移、权限判断、Consent 判断、审计、幂等或错误语义。

## 4. 明确禁止

禁止以下实现方式：

1. `if environment == test` 跳过业务校验、Consent、Audit、幂等、人工闸门或状态机；
2. 测试环境独有的业务路由、业务按钮或业务状态；
3. 生产没有的“万能测试后门”直接写入权威事实；
4. 用硬编码金额、积分、会员、成长结果或服务记录冒充正式数据；
5. 只在生产实现 Workflow，测试环境用同步函数“假装完成”；
6. 因外部供应商不可用而删除 AI/支付/通知的完整业务路径；应替换为等价的可审计模拟适配器；
7. 把 `SYNTHETIC_DEV_ONLY` 路由挂在生产应用，或让移动端依赖只有开发环境才存在的接口。

## 5. 测试环境的完整性门禁

任何场景进入“可测试”状态前，必须同时具备：

- 同一份业务流程节点契约；
- 同一组输入校验、业务规则和拒绝矩阵；
- 同一组状态机正向与反向用例；
- 同一组权限、家庭隔离、Consent、审计和幂等用例；
- 至少一条使用模拟外部依赖的完整 E2E；
- 至少一条使用 PostgreSQL 的持久化/重启回读测试；
- 测试结果能证明“数据是模拟的”，不能证明“功能被删减”。

生产发布前，必须在测试环境先通过同一套业务验收套件；生产只增加真实数据、真实供应商和容量验证，不得增加未在测试环境验证过的业务分支。

## 6. 当前仓库的整改登记

当前 `backend/apps/family_api/dev_wiring.py` 仍包含进程内 repository 和合成 Consent，属于历史开发接线，不能视为本规范的最终实现。后续必须：

- 保留同一组业务接口和规则；
- 用明确的 synthetic adapter 替换真实外部依赖；
- 让测试环境使用完整 PostgreSQL schema 和真实状态机；
- 将每一项差异登记为“数据/外部依赖差异”，不得登记为“功能差异”。

本规范与 R4（无测试不得声称能力）、R5（合成数据隔离）、R6（审计）、R8（人工闸门）、R9（AI/成长边界）共同构成验收前置条件。
