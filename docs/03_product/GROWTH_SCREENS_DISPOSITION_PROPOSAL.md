# GROWTH 四页处置建议（项目经理方案）

> **这是建议，不是裁决。** 需要 project-owner 批准后才生效。
> 但它不是又一次"请你决定"——每一页都给出明确处置、依据、以及若采纳后的施工范围。

## 0. 结论先行

**矩阵001 对这四页的 `GATE_BOUNDARY` 判定，在文案层已经过期了。**

`MIGRATION_PLAN_V2.md` 第3节写的处置是「**不迁移，不重建** —— Python 重写只会把违规语义带过去」。这个判断建立在这四页展示"成长效果/榜单/海报"的前提上。我逐页读了迁入 AiFamily 后的实际代码，**该前提已不成立**：

| 页面 | 我以为的 | 实际代码 |
|---|---|---|
| UI-08 | 复盘回读，GATE_BOUNDARY | 文案是「已看见的行动」「继续观察」「下一步可试」，且**页面自带边界声明**：「这是一份家庭过程回顾，不是儿童诊断、家庭总分或效果结论。」 |
| UI-11 | 成长效果/榜单 | 文案是「我的过程」「可暂停」「本周/本月」——纵向自比，无横向比较 |
| UI-12 | 成长海报 | 文案是「我们一起走过的片段」「**仅家庭可见**」「可继续编辑」 |
| UI-29 | 成果证明（三数字+环形指标） | `BADGES` 是三个**行为描述**：愿意倾听/坚持行动/共同回看，detail 是「为一次对话留出时间」「把小事放进日常」「记录自己的过程」 |

对四页做 grep（`排名|排行|榜|总分|超过|击败|第.名|ranking|leaderboard|score`）：**唯一命中是 UI-08 那句否定声明本身**。

我此前在功能分解书里把 UI-29 标为「⛔ 三数字+环形指标，视觉上是评分」——**那个判断是错的**，我依据的是源仓库审计的旧描述，没有读迁入后的代码。这里更正。

## 1. 逐页处置建议

### UI-29「成长成果」→ **建议保留，改名**

**处置**：`⛔ 红线禁止` → `❌ 未实现（可建）`

**理由**：`BADGES` 三项是**行为记录**而非成果评级。「愿意倾听 / 为一次对话留出时间」描述的是家庭做了什么，不是家庭得了几分。这与 R9 禁止的"家庭总分/排名"是不同的东西——R9 禁的是**比较与评级**，不是**记录与看见**。

它甚至正面符合战略定位：`COMMERCIAL_VALUE_STRATEGY §0.1`「家是港湾」要求的正是"帮助家庭看见自己的努力"，而不是"制造比较焦虑"。

**唯一需要改的**：页面名叫「成长成果」（Growth Outcomes），而 `outcome` 在本系统的领域语言里是有严格含义的一等概念（`Fact ≠ Perspective ≠ Recommendation ≠ Action ≠ Outcome`）。叫 Outcomes 会让人以为这里展示的是经过验证的成长结果。

建议改为「**成长足迹**」或「**我们做过的事**」，对应的域概念是 `Action`（已发生的行动）而非 `Outcome`（经验证的结果）。这个改名不是措辞洁癖——它决定了后端该给什么数据。

**施工范围**：三个 badge 的数据源应为真实的 `GrowthAction` 完成记录，不是硬编码数组。属 Batch 4（PLAN 闭环）的下游，不需独立立项。

---

### UI-12「成长片段」→ **建议保留，无需改动**

**处置**：`🎭 合成数据支撑` → `❌ 未实现（可建）`

**理由**：「我们一起走过的片段」+「**仅家庭可见**」+「可继续编辑」，这是家庭私有的记录本，不是对外海报。`仅家庭可见` 这个标注本身就排除了"制造比较"的可能——没有观众就没有比较。

`MIGRATION_PLAN_V2` 把它归入"海报类"是源仓库时期的判断，迁入后的实现不是海报。

**施工范围**：真实数据源是家庭自有的行动/反思记录。与 UI-29 同一批。**注意**：若未来要加"分享"能力，那时才触碰 R9 与合规第3节（向未成年人营销），届时须重新评估——但当前的"仅家庭可见"形态不触碰。

---

### UI-11「我的过程」→ **建议保留，无需改动**

**处置**：`🎭 合成数据支撑` → `❌ 未实现（可建）`

**理由**：「我的过程」「本周/本月」「上周」是**纵向自比**（这个家庭现在 vs 这个家庭之前），R9 禁止的是**横向比较**（这个家庭 vs 别的家庭）。两者性质完全不同。

`journey_route: 'growth-ranking'` 那个路由名（`DEV_SYNTHETIC_FIELD_ANALYSIS.md` R9-01 标记的）确实该改——**但那是路由命名遗留，不是这个页面的语义**。源仓库的卡片自述已经说明「用个人历史轨迹替代跨家庭排行」，即它自己知道那是旧壳。

**施工范围**：改路由名 `growth-ranking` → `growth-timeline`（属 T-04b 建议的 `/dev/*` 重构范围）；数据源为家庭自有时间线。

---

### UI-08「家庭过程回顾」→ **建议保留，作为正面样板**

**处置**：`❌ + ⛔ GATE_BOUNDARY` → `❌ 未实现（可建，优先）`

**理由**：这一页**已经做对了**，而且是全系统唯一在 UI 层自带边界声明的页面：

> 「这是一份家庭过程回顾，不是儿童诊断、家庭总分或效果结论。」

它把 R9 的三条红线（不诊断/不总分/不断言效果）直接写进了用户可见的界面。这不是合规负担，是**产品诚实性的表达**——`COMPLIANCE_HARD_CONSTRAINTS §12` 说的"不诊断不打分却依然专业陪伴，这个信任感本身就是护城河"，UI-08 是它的具体实现。

**建议把这句边界声明提升为设计规范**，其余三页在落地时照此加上。

**施工范围**：`GET /families/{id}/growth/family-review-readback`，属 Batch 4。

## 3. 真正仍需红线拦截的，只剩一项

四页里唯一我建议**维持红线**的不是页面，是 `/dev/platform-surfaces` 里的：

**`family_learning_exchange_feed` —— 写死「有家长会在情绪上来时先停一停」这类虚构他人言论。**

这不是 fixture 标注问题，是**冒充真实用户分享**。它与前四页性质不同：前四页展示的是这个家庭自己的东西，这一项是伪造别人的话给这个家庭看。社区能力（Batch 7）落地时必须用真实用户内容，不得移植这些字面量。
