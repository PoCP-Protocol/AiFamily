# Family 家庭成长体验架构与 34 UI 设计规范

## 1. UI 的定位

34 个 UI 是迁移、视觉和回归基线，不是产品上限。它们不是孤立页面，也不是业务 API 的
装饰层，而是当前家庭与平台关系的体验契约。随着家庭需求平台扩展，可以新增、合并、
重组或淘汰页面，只要新的体验更完整且不丢失原有业务语义。
每个页面必须让家庭知道：

```text
我现在的处境是什么
平台理解了什么
我可以选择什么
下一步能做什么
平台还不能替我做什么
```

视觉基线作为回归参考，但页面内容、状态和动作必须由业务投影、流程节点、权限、同意和
Principal 输出驱动，不能用硬编码文案伪装事实。基线页面如果阻碍需求闭环，可以通过
新页面或重组导航解决，不得把“已有页面”当成不改进的理由。

## 2. 情绪优先的体验顺序

```text
接住无奈/疲惫
  → 让家庭感到被看见
  → 用短而清楚的解释降低理解成本
  → 只给一个可开始的小行动
  → 即时反馈和可选下一步
  → 连续成长、真人服务和解决方案
```

情绪价值不是煽情或制造依赖。页面要允许拒绝、暂停、降低频率、清空推荐、转人工和
删除记录；商业入口在家庭明确表达服务需要后再出现。

## 3. 游戏感而非游戏操纵

允许使用：章节、任务、选择、进度、可选徽章、家庭故事和共同庆祝。

禁止使用：家庭总分、家庭排名、孩子比较、随机奖赏、倒计时惩罚、连续打卡惩罚、
以消费金额换成长地位，以及让未成年人承担商业转化压力。

进度表示“我们一起走到了哪一步”，不表示“谁比谁更好”。跳过和暂停不是失败，
而是家庭节奏的一部分。

## 4. UI 状态契约

每个 UI 至少实现以下状态，且状态必须来自接口/投影：

| 状态 | 用户应该知道什么 | 允许动作 |
|---|---|---|
| loading | 正在读取什么、预计等待什么 | 取消/返回 |
| empty | 目前没有什么，以及为什么 | 开始需求表达/返回 |
| success | 已读取或已完成的真实事实 | 查看下一步/分享（需确认） |
| draft | AI/系统只是提出了什么建议 | 编辑、确认、拒绝 |
| review_required | 为什么需要人工或家庭确认 | 查看原因、等待、转人工 |
| paused | 旅程暂停在哪里 | 恢复、调整节奏、退出 |
| denied | 哪个权限/同意/范围不满足 | 补充同意、切换主体、返回 |
| error | 发生了什么，是否可重试 | 重试、稍后、转人工 |
| deleted/expired | 哪些内容已失效或删除 | 查看权利说明、重新开始 |

UI 不得把 `draft`、`recommendation`、`action_proposal` 渲染成“已完成”“已诊断”或
“已获得结果”；业务事实必须有 Named Action 回执。

## 5. 34 UI 的体验分层

- **关系入口**：UI-01、UI-33。让家庭感到被欢迎、可管理成员和可控制数据。
- **教育理解**：UI-02、UI-02-result、UI-03、UI-04、UI-05。完成测评、证据解释、
  需求澄清和教育方案确认。
- **成长游戏**：UI-09、UI-10、UI-11、UI-12、UI-29。提供章节、今日小行动、过程
  回顾和故事沉淀，不做排名。
- **服务信任**：UI-06、UI-19～UI-24、UI-31、UI-34。展示真人服务、响应、交付、
  验收、补救和服务记录。
- **产品与关系**：UI-07、UI-13～UI-18、UI-30、UI-32。家庭主动表达需要后展示
  产品、会员、权益、邀请和资产。
- **家长社区**：UI-25～UI-28。默认私密、家长确认可见、可撤回和可申诉。

每个页面必须绑定一个业务场景、一个流程节点、一个权威投影和一个主要动作；跨页面
跳转必须携带 `family_id`、主体范围、目的和 correlation 链。新页面可以超出原编号体系，
例如“家庭需求中心”“解决方案工作台”“服务案件跟踪”“家庭支持圈”，但必须先证明它
补齐了现有流程缺口或显著降低了家庭理解成本。

UI 基线默认不改编号和核心语义；允许通过新路由、页面合并、页面拆分或导航重构提升
体验。任何变化都必须保留迁移映射、回归截图/交互测试和业务场景追踪；不能以“基线不变”
掩盖用户体验问题。

## 6. 推荐与内容发现体验

对标内容平台的顺滑发现，但只推荐与家庭已授权目的相关的内容、行动或服务：

- 每张推荐卡显示“为什么给我看”；
- 提供不感兴趣、稍后、暂停、降低频率和清空入口；
- 推荐使用家庭节奏和明确反馈，不以停留时长单独排序；
- 未成年人上下文不得驱动商业推荐；
- 多语言保留原语言引用，缺少可靠翻译时转人工或明确不可用。

## 7. 多模态体验架构

家庭表达和陪伴不能被限制为文字输入和静态图片。多模态是家庭需求平台的基础交互层：

```text
文字 / 语音 / 图片 / 音频 / 视频 / 互动卡片
  → MediaSession（同意、租户、家庭、主体、语言、目的）
  → 转写 / OCR / 内容安全 / 时间轴对齐
  → EvidenceReference / ContextSnapshot（只读、可过期）
  → Principal 解释、行动或方案草案
  → 文字、语音、音频、短视频、互动卡片或人工响应
```

### 7.1 模态能力

- **语音**：家长可口述家庭处境，孩子可选择听取小行动；转写结果必须可查看、可修改、
  可删除，原始音频和文本分开留存。
- **图片**：可上传家庭手写记录、作业或生活观察；OCR/视觉解释必须标注不确定性，
  不把图像直接当作诊断或事实。
- **音频/短视频**：用于情绪承接、示范练习和服务说明；必须有字幕、文字摘要、播放失败
  和低带宽降级，不以自动播放制造沉迷。
- **互动卡片（InteractiveCard）**：用选择、拖拽、时间线和章节表达一个小行动；点击“完成”只产生候选
  记录，事实仍需 Named Action 或用户确认。
- **跨模态同步**：每个输出记录 modality、语言、版本、来源和替代文本；家庭可以随时
  从语音切换文字、从视频切换摘要、从互动切换无障碍模式。

### 7.2 多模态安全与数据边界

- 每种模态单独声明采集目的、主体、同意、留存期限和删除引用；未授权不得上传或处理。
- 原始媒体、转写/OCR、Embedding、摘要和 AI 输出分层存储，均继承 tenant/family/subject
  隔离，不能进入公共知识库或跨租户缓存。
- 媒体解析失败、语言不支持、内容风险不明、区域策略不允许时，必须明确降级、转人工或
  返回不可用，不得静默猜测。
- 儿童语音、面部、影像和家庭私密场景默认按高敏感数据处理，不用于商业推荐或排名。
- 视觉、声音、动效不能成为唯一信息载体；所有关键内容必须提供文本、字幕、替代文本和
  可暂停控制。

### 7.3 第一条纵向切片的多模态最小范围

UI-03 先支持“文字 + 语音口述”需求表达，UI-05 支持“文字 + 互动方案卡”，UI-09 支持
“文字 + 语音/音频行动引导”。测试环境使用合成音频和图片适配器，接口、权限、错误码、
删除和人工升级路径与生产一致；后续再增加真实图片、视频和更复杂的视觉理解。

## 8. 服务与解决方案体验

家庭不需要理解内部组织结构。对外始终是一个 Family 关系入口，内部由校长、教育者、
专家、管家和 FGCN 伙伴协作。页面呈现的是：需求被理解、方案如何形成、谁负责、何时
交付、怎样验收、出了问题谁接住。

产品是标准化供给，服务是交付过程，解决方案是围绕家庭需求组合出来的可执行蓝图。
UI 不得把“资源很多”当作“质量很高”；质量必须展示来源、适用范围、SLA、验收和
补救路径。

## 9. 多语言、多租户和无障碍

- 文案、知识、错误码和人工队列分别拥有 `user_locale`、`content_locale`、
  `model_locale` 和 `policy_locale`；
- UI 所有请求由租户和家庭作用域解析，禁止跨租户推荐、缓存、Embedding 和投影；
- 原始家庭表达保留原语言引用，翻译后的解释标注语言和版本；
- 页面支持字体放大、屏幕阅读器、窄屏、不确定状态和低带宽重试；
- 视觉温暖不等于降低可读性，颜色、动画和声音不得成为唯一信息载体。

## 10. UI 完成定义

一个 UI 纵向切片只有同时具备以下证据才可标为 `E2E_READY`：

1. 可从真实入口到达，绑定业务场景和流程节点；
2. 使用后端投影/Named Action，不依赖假成功 fixture；
3. 覆盖 loading、empty、success、draft/review、denied、error、paused 等必要状态；
4. 对 AI 输出显示来源、边界、确认和撤回；
5. 成功、拒绝、超时、重试、重复提交和删除测试通过；
6. dev/test/prod 使用同一 API、状态机、错误码和闸门；
7. 多语言、租户隔离、无障碍和隐私可见性有测试证据。

## 11. 第一条开发路径

第一 Sprint 优先完成 UI-03 → UI-05 → UI-09：

```text
UI-03 被理解/需求澄清
  → UI-05 教育方案草案/家庭确认
  → UI-09 一个小行动/暂停或完成
  → 反馈和下一步推荐
```

这条路径通过后，再把同样的体验契约复制到服务、产品、解决方案、社区和商业关系页面。
