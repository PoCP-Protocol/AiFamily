# AiFamily 全量 MVP 场景 PRD V2

> 这是面向实施的 PRD 评审稿。每个场景都同时写用户目标、交互、业务对象、失败恢复和可执行验收；“文档完成”不代表“功能完成”。

## 0.1 全量 MVP 发布契约

第一阶段发布对象是一个完整的家庭价值闭环，而不是 S1 的技术 MVP。S1–S6 必须在同一产品上下文中可进入、可完成或明确退出：

```text
家庭困扰 → 测评理解 → 家长确认 → 成长实践/复盘
       ↘ 知识与 AI 解释
       ↘ 专业服务履约
       ↘ 受控家庭关系连接
       ↘ 明确需要后的会员/方案选择
```

每个场景的最小交付必须同时具备：

1. 一个家长可操作的入口和结果页；
2. 一个真实业务对象/状态写入或明确的只读事实来源；
3. 一条正向路径、一条失败/拒绝/恢复路径；
4. 可回放的场景测试和可展示 artifact；
5. 与前后相邻场景的 contract，而不是孤立 demo。

未完成其中任一项，该场景只能标 `NOT_IMPLEMENTED`，不能计入全量 MVP 完成率。并行开发只改变交付顺序，不改变全量范围。

## 0. 共同用户语言

平台对家长说人话，不显示 `DTO`、`route`、`fixture`、`provenance`、`idempotency` 等工程术语。用户看到的是：我说了什么、平台理解了什么、我可以确认/修改什么、下一步会发生什么。

所有页面必须有 loading、空态、成功、拒绝、过期、撤回、权限不足、冲突、后端不可用和可恢复错误状态。视觉交付必须包含真实层级、图片/插画、字体、间距、动效和内容层次，不用测试文案冒充产品文案。

## 1. S1｜第一次被理解：家庭测评到确认重点

### 用户故事

作为第一次进入 AiFamily 的家长，我希望从一个真实困扰开始，通过几个有意义的问题，看到平台对家庭处境的解释，并能修改或确认重点，而不是被打分或被诊断。

### 主流程

1. 首页选择“我想先理清家里最近的一件事”。
2. 家长选择家庭成员/主题并回答版本化测评问题；可暂停后继续。
3. 提交后生成不可变测评证据和可读的家庭观察摘要。
4. AI/规则生成带证据引用的 `GrowthHypothesis`，显示“这是我们目前的理解”。
5. 家长可以确认、修改关注点、暂不处理或退出。
6. 只有确认才产生 `GrowthIntent`，并进入 S2。

### 用户可见结果

- “你刚才提到的三件事之间，可能都卡在……”。
- “这是一个可以继续讨论的理解，不是结论。”
- “你可以告诉我们哪里不准确。”
- 确认后显示“接下来我们会围绕这个重点陪你观察”。

### 业务契约

| 项目 | 要求 |
|---|---|
| 输入 | tenant/family/actor、测评版本、回答、家庭需要 |
| 输出 | immutable evidence、hypothesis、evidence_refs、knowledge_refs、确认 receipt |
| 写入 | 仅具名 Action；同事务 Audit/Outbox；幂等重放 |
| 失败 | 未授权、跨家庭、工具过期、AI 不可用、重复提交均可读且 fail-closed |
| 禁止 | 家庭总分、诊断、AI 自动确认、儿童画像营销 |

### 完成条件

S1 必须有真实应用层和 HTTP 场景测试，覆盖首次完成、暂停恢复、确认、驳回、撤回、跨家庭、重复请求、AI provider 缺失；用户可在 UI 中完成而不是仅调用 service。

## 2. S2｜把理解变成家庭成长循环

### 用户故事

作为已确认重点的家长，我希望知道这份计划为什么适合我们，能在生活中实践、记录真实观察，并在一段时间后复盘是否继续、调整或暂停。

### 主流程

1. 从 S1 receipt 生成带 evidence/knowledge 引用的成长计划。
2. 家长确认计划的目标、节奏和第一阶段关注点。
3. 选择一个有明确理由的家庭实践，不以完成次数制造压力。
4. 记录发生了什么、哪里有阻碍、家庭成员如何回应。
5. 阶段复盘：继续、调整、暂停；每个决定都可回读。

### 用户可见结果

计划页必须回答“为什么是它”；记录页必须让家长写具体发生的事；复盘页展示“我们观察到了什么、还不知道什么、下一步有哪些选择”，不显示虚假的疗效或排名。

### 业务契约与完成条件

`JourneyPlan`、`FamilyPractice`、`PracticeRecord`、`PhaseReview` 必须 tenant/family scoped；同一请求跨进程重放返回同一响应；写入和 canonical Audit/Outbox 同事务；新会话回读完整链路；真实 PostgreSQL 和 HTTP E2E 必须通过。

## 3. S3｜知识库与 AI 共同理解

### 用户故事

作为家长，我希望平台解释“为什么会这样、有哪些可能的做法、这些依据来自哪里”，并能把专业知识翻译成我能理解的语言；我不希望看到无法核对的 AI 断言。

### 主流程

1. 根据 S1/S2 的明确需要检索版本化知识条目。
2. 将家庭证据和知识引用交给 Model Gateway。
3. 生成 Perspective、Recommendation 或风险草案，附模型/版本/依据。
4. 家长或授权人工确认、编辑、拒绝；确认前不改变权威事实。
5. 将使用过的知识和结果写入可回放 provenance。

### 完成条件

必须有固定数据集 replay、引用准确性、prompt injection、PII 泄漏、provider timeout/cost limit、模型不可用和人工接管测试；所有领域调用只能经过 Model Gateway。

## 4. S4｜从家庭需要到专业服务

### 用户故事

作为已经明确需要外部帮助的家长，我希望看到适合当前问题的老师/专家/机构，知道服务内容、时间、费用和交付方式，并能追踪履约和获得补救。

### 主流程

1. 家长主动从确认的需要进入服务入口。
2. 查看服务说明、适用范围、负责人和可用时间。
3. 创建预约/服务意向，价格和授权范围明确。
4. 服务方接受并形成 DeliveryRecord。
5. 家长反馈 helpful/somewhat/not helpful；异常进入人工补救。

### 完成条件

预约、容量、取消、履约、回访、补救和幂等均有场景测试；不把测评结果自动转成购买，不向孩子推销，不用 AI 自动派单或结算。

## 5. S5｜家庭关系网络（全量 MVP 的最小形态）

### 用户故事

作为家长，我希望在明确主题下看到真实、经过审核的家庭经验，参与活动或互助，而不是被无尽信息流和陌生人私聊打扰。

### MVP 形态

只做主题活动/经验卡/收藏回看/报名意向；发布者、可见范围、审核状态、撤回和举报可追踪。首版不做开放陌生人私聊、热榜、家庭排名或自动推荐。

### 完成条件

至少有一个合成数据端到端场景和审核/撤回/越权反例；真实社区内容未形成前，UI 必须显示空态而不是伪造他人发言。

## 6. S6｜基于明确需要的会员与购买（全量 MVP 的最小形态）

### 用户故事

作为家长，我希望在真正理解需要之后选择会员、服务或商品，清楚知道得到什么、花多少钱、如何取消和如何获得帮助。

### MVP 形态

先完成产品目录、方案比较、购买意向、权益读取和履约反馈；支付可使用隔离测试适配器，但不得把测试订单当真实收入。推荐必须由家长主动表达的需要触发，不从孩子画像推送。

### 完成条件

会员、贡献、现金分账；价格和权益来自后端 canonical DTO；订单状态、取消、退款/补救可回读；合成支付 provider 与生产 provider 物理隔离。

## 7. 全量 MVP 验收矩阵

| 场景 | 最小可运行主链 | 必须展示的结果 | 未通过时的真实状态 |
|---|---|---|---|
| S1 | 困扰→测评→理解→确认/拒绝 | 家长看见可修改的理解 | `S1 NOT_IMPLEMENTED` |
| S2 | 意图→计划→实践→观察→复盘 | 新会话仍能回读家庭过程 | `S2 NOT_IMPLEMENTED` |
| S3 | 需要→知识引用→AI Draft→确认/拒绝 | 解释有依据且可追溯 | `S3 NOT_IMPLEMENTED` |
| S4 | 需要→服务→预约→履约→反馈/补救 | 家长知道谁交付、如何恢复 | `S4 NOT_IMPLEMENTED` |
| S5 | 主题→审核经验/活动→加入/收藏→退出/举报 | 真实可见范围和关系连接 | `S5 NOT_IMPLEMENTED` |
| S6 | 需要→方案→权益→购买意向→取消/反馈 | 价格、权益、履约清楚 | `S6 NOT_IMPLEMENTED` |

全量 MVP 的完成判据是六行全部具备代码、场景测试和可展示结果；不能用 S1 的高质量替代 S3–S6 的缺失。

## 8. 统一产品指标

不以页面数量衡量进度，按以下用户结果衡量：

- 首次到达完成率：家长是否完成 S1 并确认/有意拒绝，而不是被迫点过按钮。
- 被理解感：家长是否能指出“平台理解对了/错在哪里”。
- 证据完整率：从 S1 到 S2 的引用、确认、实践、复盘是否可回放。
- 恢复成功率：拒绝、撤回、错误、暂停后是否能继续或明确退出。
- 服务帮助感：S4 完成后家长是否能评价交付并触发补救。

禁止用家庭总分、横向排名、儿童画像或增长刺激指标替代上述产品指标。
