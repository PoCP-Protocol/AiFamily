# 家庭教育与家庭成长移动产品研究要点

## 研究口径

本文只记录可用于产品设计的外部研究结论。三份核心 PPT、榜样教育课程和 Family AI 内部规格属于产品与设计输入，不能单独证明教育效果。移动 App 的任何打卡、反思和持续使用数据只能证明发生了过程行为，不能自动证明孩子成长结果或因果效果。

## 外部证据与产品含义

| 研究结论 | 产品含义 | 证据边界 |
|---|---|---|
| 技术辅助育儿项目的系统综述发现，让家长参与设计、提供个性化或可调整内容、给予用户控制权和实际支持，与更高参与度存在初步关联。[1] | legacy UI 不应只提供统一课程列表；首页要允许家长选择当前关注点、每天投入时长和适合家庭的行动强度，并提供可暂停和恢复的计划。 | 该综述指出参与定义和测量差异较大，结论是初步关联，不等于这些功能必然改善儿童结果。 |
| 数字化育儿干预常见内容包括视觉或视听知识、在线专业支持、反馈循环和育儿技能练习。[2] | 21 天成长营应采用“一段简短说明 + 一个家庭微行动 + 一次可选反思 + 一个下一步提示”，专家支持作为可选升级路径，而不是把长课件搬进手机。 | 文献数量有限，部分研究设计质量不一；内部课程仍需持续验证。 |
| 针对低中收入环境的综述显示，数字干预对家长层面的知识、行为和心理状态更常报告正向影响，但儿童直接测量结果并不一致。[3] | 移动端首先反馈“家长今天做了什么、学到了什么、感受如何”，不得把完成任务显示成“孩子能力提升”或“家庭成长得分”。 | 家长报告和直接测量不可混用；Outcome 必须独立采集并标注来源。 |
| 有效数字项目常把提示、建议行动和鼓励组合起来，并嵌入日常活动，如阅读、吃饭、玩耍和家务。[3] | 任务设计优先选择家庭日常可执行场景；每个任务显示预计时长、需要材料、参与者和适用情境，减少额外负担。 | 不同年龄和文化情境需要适配，不能直接复制单一研究课程。 |
| 儿童与青少年数字干预研究普遍缺少对公平访问和“有效参与”的系统测量。[4] | App 要支持低认知负担、短文本、清晰语音/图片入口和弱网恢复；参与指标应区分打开、阅读、开始、完成和反思，而不是只统计登录次数。 | 使用频率不等于有效参与，更不等于结果。 |

## 可执行设计原则

1. **微行动优先。** 每天只突出一个最值得做的家庭行动，其他内容作为可选支持，避免首页成为功能目录。
2. **用户控制。** 家长可以调整时间、暂停计划、跳过不适用行动并说明原因，系统据此生成规则化下一步，而不是强迫连续打卡。
3. **家庭共同完成。** 任务明确家长、孩子或共同参与角色；孩子表达默认是 Perspective，并有单独可见性边界。
4. **反馈分层。** 完成状态属于 Action；反思属于 Perspective；课程建议属于 Recommendation；可核验的观察才可能成为 Fact。
5. **专业支持可达。** 当家长需要更多帮助时，进入专家目录、咨询需求草稿或服务记录，但不从普通任务直接触发外部预约。
6. **不以排名促活。** 不使用家庭排名、总分、儿童诊断或焦虑式连续打卡；用节奏、回顾和可恢复计划支持长期参与。
7. **研究可迭代。** 记录每个功能来源、假设和验证指标，为后续课程和算法迭代提供可追溯依据。

## 对 legacy UI 的直接影响

| UI 范围 | 研究驱动的设计重点 |
|---|---|
| UI-01~UI-10 | 今日一件事、测评选择、规则解释、90 天计划、行动打卡、家庭回顾和孩子友好练习 |
| UI-11~UI-12 | 用旅程和故事呈现过程，不呈现家庭排名或诊断性结论 |
| UI-13~UI-18 | 课程、工具、权益和积分围绕家庭实际需要，Dev 中只形成意向、内部权益和账本回读 |
| UI-19~UI-24 | 专家支持、咨询草稿、活动意向和服务记录形成可恢复的人工协同路径 |
| UI-25~UI-28 | 社区内容与私有分享分开，默认家庭私有，不把儿童内容自动公开 |
| UI-29~UI-34 | 成长回顾、会员、资产、家庭资料和记录必须显示来源、时间和可见性 |
| UI-35 | 21 天课程采用每日微行动、可选反思、节奏回顾和专业支持入口，不承诺 21 天产生确定教育结果 |
