# 波波校长研究与 Family AI 移动产品设计转化

**作者：Manus AI**  
**研究用途：Family AI iOS/Android 移动 App，UI-01 至 UI-35**

## 一、研究结论

波波校长相关材料最有价值的部分，不是把一个真人简单复制成聊天机器人，而是把一种可被用户感知的家庭教育服务方式转化为稳定的移动产品能力：先接住家长当下的情绪和困扰，再把问题放回具体家庭场景，给出今晚能够执行的一件小事、一句可以直接说出口的话和一个第二天可以观察的信号。内部材料把这种角色概括为“家庭成长校长”，公开材料则把课程与“父母二次成长”、智慧父母训练和长期陪伴联系起来。[1] [2]

但公开资料存在明显证据限制。课程数量在不同资源分享页中出现 29 集与 33 集两种口径；机构规模、粉丝数量、服务家庭数量和课程效果主要来自宣传稿或自媒体页面；公开短视频主页需要登录，无法完整核对内容列表。因此，移动 App 可以吸收**课程结构、内容表达和陪伴节奏**，但不能把宣传数据、资源分享目录或用户故事写成产品事实，更不能把波波校长观点直接写入 Family 核心本体。[3] [4] [5]

> **产品裁决：** 移动端第一版使用 Family AI 自有角色“法咪莉校长”，吸收波波校长材料中的温暖、直接、低剂量行动和陪伴节奏；除非后续完成肖像、声音、名称和内容授权，不对外声称“就是波波校长本人”，也不克隆真人声音或身份。

## 三、波波校长方法的可复用产品结构

### 3.1 标准陪伴回应

移动端“问校长”和“今晚怎么说”不应输出一段泛泛的长回答，而应固定为七个可审计部分。

| 层次 | 用户看到的内容 | 数据性质 | 写入边界 |
|---|---|---|---|
| 接住 | 简短复述家长的困扰，不评判 | Perspective summary | 不写入 Family Fact |
| 场景 | 时间、地点、参与者、触发事件 | Candidate Fact | 需用户确认后才能成为 Observation |
| 多视角 | 家长视角、孩子可能视角、关系视角 | Perspective / Hypothesis | 必须明确“可能”，不得诊断 |
| 今晚一件事 | 10 分钟以内的低剂量家庭行动 | Recommendation | 用户确认后才创建 GrowthAction |
| 今晚怎么说 | 温和版、边界版、青春期版话术 | Recommendation | 只作为草稿，用户决定是否采用 |
| 看一个信号 | 可观察、非诊断性的行为信号 | Observation prompt | 不自动推导 Outcome |
| 明天复盘 | 家长填写发生了什么和自己的感受 | Perspective + Action receipt | 不把反思当作孩子事实 |

### 3.2 内容表达

“法咪莉校长”的移动端语气应保持**温暖但不讨好、专业但不压人、坚定但不控制**。每次交互先降低家长的羞耻和焦虑，再给出一个可执行下一步；避免连续输出理论、吓唬家长、把父母描述成唯一责任人，或把孩子贴上“懒惰、叛逆、失败型”等标签。

| 应使用 | 应避免 |
|---|---|
| “先不用急着解决全部问题，我们今晚只观察一次。” | “你的教育方式导致了孩子的问题。” |
| “这只是一个可能视角，你可以看看是否符合你们家的情况。” | “孩子就是缺乏自驱力。” |
| “你可以试试这句话，也可以改成更像你的表达。” | “必须按这个方法说才有效。” |
| “完成代表这次行动发生了，不代表已经产生教育效果。” | “连续打卡 21 天，孩子一定会改变。” |

## 四、21 天智慧父母成长营的移动端课程设计

### 4.1 三阶段结构

| 阶段 | 天数 | 家长目标 | 每日产品结构 | 阶段输出 |
|---|---:|---|---|---|
| 观察与连接 | Day 1–7 | 从急于纠正转向看见场景、情绪和互动模式 | 1 个情境说明、1 个观察任务、1 句连接话术、晚间反思 | Day 7 参与小结：做过什么、哪些场景常出现、仍不确定什么 |
| 沟通与习惯 | Day 8–14 | 练习边界表达、倾听、共创规则和微习惯 | 1 个沟通工具、1 个低剂量行动、1 个可观察信号、失败后恢复方案 | Day 14 练习小结：已尝试工具、家庭偏好、下一阶段建议 |
| 反思与延续 | Day 15–21 | 识别可持续做法并形成后续成长重点 | 1 个整合行动、1 次家庭小会、1 个复盘问题、1 个后续选择 | Day 21 过程报告和 90 天计划推荐草稿；不自动建计划 |

### 4.2 每日行动卡

每日卡片必须控制在一屏完成核心理解。它包含“为什么做”“今晚做什么”“可以怎么说”“观察什么”“完成后写一句话”五部分。默认预计用时 5–15 分钟，不用连续打卡惩罚家长。跳过任务时，家长可以选择“今天不适合”“孩子不愿参与”“我需要先照顾自己”“内容不适用”或自定义原因；系统据此调整推荐，但不能将跳过解释为失败。

### 4.3 课程主题来源

公开资源目录显示的高频主题包括坏习惯、父母目标、焦虑和消极情绪、教养信念、亲子关系修复、沟通、学习习惯与学习动力。[4] [5] 这些主题可作为课程选题池，但不直接采用公开资源页的课时顺序。最终每日课程必须经过内部课程专家审定，并记录 `source_id`、`review_status`、`age_band`、`risk_level`、`expected_minutes` 和 `evidence_boundary`。

## 五、对 35 个 UI 的精确映射

| UI | 页面 | 波波校长研究的移动端转化 |
|---|---|---|
| UI-01 | 家庭成长首页 | 增加“今晚一件小事”“问法咪莉校长”“21 天成长营”三个主入口；首页首先显示家庭行动而不是课程商城 |
| UI-02 | 家庭测评 | 用高频家庭场景选择代替诊断题；明确测评只是家长视角 |
| UI-03 | AI 成长诊断报告 | 改名为“家庭成长解读”；呈现事实、视角、假设、建议分层，不使用儿童诊断 |
| UI-04 | 90 天成长方案 | 把 21 天营产生的过程记录转成待确认的优先级与计划草稿 |
| UI-05 | 90 天陪跑与社群 | 引入固定陪伴节奏、阶段复盘和人工顾问入口；社群内容默认不公开儿童信息 |

| UI-10 | 成长小助手 | 以孩子自主和表达为中心；不把家长端建议直接展示为孩子结论 |

| UI-33 | 家庭档案 | 保存家庭成员、角色、同意、可见性和成长重点；不保存标签化诊断 |
| UI-34 | 服务记录 | 区分服务发生、顾问记录、家长反馈和结果证据 |
| UI-35 | 21 天智慧父母成长营 | 三阶段课程、每日行动卡、复盘、Day 7/14/21 小结和 90 天推荐草稿 |

## 六、人工服务与社群边界

当输入涉及自伤、家暴、虐待、严重心理危机、医学诊断或违法风险时，法咪莉校长停止普通陪练，显示清晰的人工求助建议与服务入口。移动端不能自动为家庭创建付费咨询、通知专家或联系外部人员；所有预约、分享、外发和通知在 Dev 环境中保持受控 no-op，并明确显示“已保存意向，未实际外发”。

社区中的“校长点评”不是模型自由生成的公开裁决。它应先形成内部草稿，经规则检查和人工审核后才能发布。孩子相关内容默认家庭私有，公开前必须由家长确认可见性和去标识化处理。

## 七、开发优先级

| 优先级 | 移动纵切 | 原因 |
|---|---|---|
| P0 | UI-01 → UI-09 → UI-35 | 直接形成“今天看见什么—今晚做什么—完成与反思—明天继续”的家庭行动闭环 |
| P1 | UI-02/07 → UI-03/08 → UI-04 | 把场景输入、结构化解读和 90 天计划连接起来 |
| P1 | UI-19/20 → UI-21 → UI-24 | 形成 AI 陪练到人工支持的可控升级路径 |
| P2 | UI-25 → UI-26 → UI-27/28 | 在隐私与审核边界内形成家长互助循环 |
| P2 | UI-13/14 → UI-18/30 → UI-32 | 形成产品、权益、会员和资产回读，不接真实支付 |

## 八、必须继续核验的问题

当前公开资料仍不能独立确认波波校长的学历、专业资质、粉丝总量、服务家庭数量、团队规模、课程完成率和教育效果；也不能确认市场流传的 29/33 集目录是否获得官方授权。上述信息在 App 上不应出现，除非取得一手证明、使用授权和内部审核决定。
