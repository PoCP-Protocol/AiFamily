# UI-13 至 UI-18 商业权益基线复核

## 全局规则

本轮以及后续页面开发均以既有 UI-01 至 UI-35 基线为产品边界。实现必须保留页面名称、主要功能点、状态、入口出口、信息层级和六循环血缘；移动端只做原生交互、展示适配与受控草稿，不把不同基线页面合并为通用模板。

## UI-13 家庭成长商城

- 原始基线：`commerce-01-mall-home.png`，239×545。
- 首屏结构：顶部标题与家庭问候；蓝色横幅邀请模块；两行六宫格业务入口；“今日推荐”横向商品区；底部五标签导航。
- 视觉约束：白底，深色正文，蓝色主行动，橙/绿/紫作为业务入口识别色；商品卡使用插画封面、标题、价格和购买人数层级。
- 功能血缘：商城按家庭需要承载拼团、成长权益、积分、会员、邀请等入口，并从推荐商品进入 UI-14。
- 移动适配：保留横幅、六入口、推荐货架和底部导航的顺序；数据优先读取 Family API 商品目录与权益投影，不把商城改成普通列表页。

## UI-14 产品详情

- 原始基线：`commerce-02-product-detail.png`，240×545。
- 首屏结构：导航栏；大幅课程主视觉；商品标题与副标题；原价、拼团价、会员价三层价格信息；服务保障；“你将获得”四项交付内容；分享得成长权益提示；底部收藏、客服、购买、拼团行动栏。
- 视觉约束：主视觉占首屏上部，价格使用红/橙强调，蓝色与橙色双主行动固定在底部；内容以横向图标组呈现。
- 功能血缘：从 UI-13 商品卡进入，方案意向后回读 UI-32；会员价与权益状态来自 UI-18/会员投影。
- 移动适配：保留信息顺序和双行动栏，但在 Dev 中“立即购买/发起拼团”只形成受控意向草稿，不产生订单、支付、库存锁定、分享或通知。

## UI-15 邀请有礼

- 原始基线：`commerce-03-invite.png`，240×545。
- 首屏结构：顶部标题；蓝色“邀请 3 个家庭”目标；已邀请家庭 1/3 进度卡；两行四项阶梯成长权益；蓝色“立即邀请”行动；微信好友、朋友圈、生成海报三种入口；底部品牌与二维码区。
- 视觉约束：浅蓝渐变背景，白色权益卡，蓝色主行动，橙色权益图标；进度数字和进度线是首屏核心信息。
- 功能血缘：单层邀请换取成长权益，并回读邀请记录；不形成多层返佣。Dev 中保留邀请草稿、目标进度和权益说明，不调用微信、海报、二维码或外部通知。
- 移动适配：保留 1/3 进度和四级权益结构；三个外部入口均返回清晰 no-op 回执，避免把用户带入不可完成流程。

## UI-16 家庭同行计划

- 原始基线：`commerce-04-group-buy.png`，244×545。
- 首屏结构：顶部“拼团专区”和副标题；全部、课程服务、会员卡、工具包四分类；纵向方案列表；每项显示方案名、团长、剩余成团人数、参与头像、剩余时间、原价、同行价与橙色“去拼团”行动。
- 视觉约束：白底列表卡，橙色价格与行动，蓝色当前分类；信息密度高但每个方案保持同一行列关系。
- 功能血缘：基线命名为拼团，产品语言调整为“家庭同行计划”，但必须保留分类、人数、规则、取消与恢复；Dev 中只形成参与意向，不创建订单、库存或支付。
- 移动适配：保留列表结构和人数状态；倒计时只作为 synthetic 方案可见期，不制造焦虑或宣称真实库存；进入方案后保存同行意向草稿。

## UI-17 成长积分

- 原始基线：`commerce-05-points-task.png`，244×545。
- 首屏结构：顶部“积分商城”与明细/规则入口；蓝色积分余额卡；“任务中心”纵向任务列表，每项显示任务、积分值和“去完成”按钮；“积分兑换”横向权益商品卡，显示所需积分和立即兑换行动。
- 视觉约束：蓝色余额卡是首屏主视觉，金色积分图标强化权益属性；任务列表为紧凑单行结构，兑换区使用四列商品卡。
- 功能血缘：积分来源于学习、行动和服务任务，账本与规则可回读；不奖励公开儿童隐私或刷屏邀请。
- 移动适配：保留余额、任务、兑换三段结构；任务动作路由到既有 legacy UI 页面；Dev 中只读积分与账本投影，领取/兑换返回受控回执，不真实发放权益。

## UI-18 会员中心

- 原始基线：`commerce-06-mine-member.png`，244×545。
- 首屏结构：顶部“我的”；用户头像、昵称和成长达人标签；已邀请、拼团、成长积分、可用奖励四项摘要；等级进度与皇冠；我的订单、邀请记录、奖励明细、专属海报、会员权益、客服支持六项入口；年度会员服务深色卡；底部五标签导航。
- 视觉约束：浅蓝会员头卡、白色功能列表、深蓝年度会员卡，成长金作为等级和会员强调；信息结构从身份、资产摘要、功能入口到年度会员服务逐级下沉。
- 功能血缘：统一回读会员状态、可用权益、积分、邀请记录与服务入口，并连接 UI-30 年度陪伴和 UI-32 订单资产。
- 移动适配：保留摘要、等级、六入口和年度会员卡；数据优先读取会员与权益投影，续费、客服、海报、支付和外部通知保持 Dev no-op 或受控意向。

## 六页基线结论

UI-13 至 UI-18 不是六个可互换的通用卡片页，而是商城首页、产品详情、邀请进度、同行方案列表、积分任务/兑换和会员资产中心六种不同页面结构。实现必须分别保留各自的首屏层级、主要状态和入口出口，同时把商品、会员、积分和权益数据统一回读自现有 Family API。

## 既有资源复用映射

| UI | 必须复用的既有资源 | 移动端允许新增的内容 | 禁止重新实现 |
|---|---|---|---|
| UI-13 | `GET /families/{familyId}/orchestration/test-loop/commerce/products`、Web `commerceMall()`、原始商城基线 | 商品目录的移动展示适配、场景筛选状态 | 新商品主数据、独立商城后端 |
| UI-14 | 商品目录、`POST .../commerce/order-intents`、商业客户投影、Web `familyContentDetailPanel()` | 方案详情展示和幂等意向提交 | 订单、支付、价格计算、库存 |
| UI-15 | Web `familyInvitationDraftPanel()`、现有 Dev flow receipt、原始邀请进度基线 | 家庭私有邀请说明草稿、no-op 回执 | 联系人读取、微信发送、海报或二维码生成、奖励发放 |
| UI-16 | Web `familyStudyGroupDraftPanel()`、商品目录、现有 Dev flow receipt、原始拼团列表基线 | 共学/同行意向草稿、人数选择与取消 | 拼团订单、倒计时库存、通知、支付 |
| UI-17 | `GET .../membership/customer-projection` 的 `dev_points`、商业客户投影、Web `familyPointsProjectionPanel()` | 积分任务路由和只读账本展示 | 生产积分余额、提现、兑换和权益发放 |
| UI-18 | `GET .../membership/plans`、`GET .../membership/customer-projection`、Web `familyServiceScopePanel()`、会员原始基线 | 会员状态与权益移动展示、续费意向草稿 | 新会员模型、扣款、续费、外部客服或通知 |

现有商业契约只允许 UI-14/UI-17 提交商业意向，现有会员写操作只允许 UI-30/UI-31/UI-32。因而 UI-18 必须保持会员与权益只读；UI-15/UI-16 使用家庭私有受控草稿和 Dev flow receipt，不绕开既有准入规则。
