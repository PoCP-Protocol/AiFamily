# UI-29 至 UI-34 基线审计

## 来源与实施原则

本轮页面严格沿用 `platform-family-growth-vertical-slice-001` 分支中 legacy UI 的原始参考图，并以 `design.md`、`lib/family/ui-registry.ts` 和现有 Family API 投影为共同来源。移动端只能做导航、展示、可编辑家庭私有草稿与离线回读适配；不得新建第二套会员、资产、档案或服务业务规则。

## UI-29 成长成果

原始基线以顶部标题、蓝色周期成果总览、荣誉激励、前后对照和“生成成长海报”行动组成。移动实现必须保留“周期回看—过程里程碑—阶段报告—继续回看档案”的层级；但不得显示成长值、家庭排名、儿童能力比较、前后因果结论或儿童照片。蓝色总览将改为过程行动、已记录里程碑和家庭确认状态；荣誉图标改为家庭过程标签；对照区只呈现家长视角与已确认行动，不推导 Outcome。

## UI-30 年度陪伴方案

原始基线以家庭成员头卡、权益/服务摘要、快捷入口、当前陪伴服务卡和深蓝年度会员横幅组成。移动实现必须保留“陪伴状态—四项摘要—六个服务入口—当前计划—年度权益”的结构。成长积分、家庭等级、累计服务和邀请奖励只能读取现有会员投影或显示未知状态；年度续费仅保存意向草稿，不能扣款、自动续费、发放权益、发送邀请或通知。

## 待完成图像复核

UI-31 至 UI-34 将继续按原始 `my-services`、`orders-assets`、`family-profile` 和 `service-records` 基线分别核对后再进入编码。每页的运行态核对将追加到本文档。

## UI-31 我的服务

原始基线以蓝色 90 天计划进度总览、四个服务角色入口、本周任务清单及“查看方案/继续打卡”双行动组成。移动实现必须保留“当前计划—服务支持—本周事项—服务记录”的层级，但进度只能来自现有计划、行动和服务投影；不得显示未经验证的完成率、AI 超能力、专家已联系或服务已完成状态。四个入口将进入既有的计划、咨询、活动和服务记录页面。

## UI-32 订单与资产

原始基线以四项交易摘要、订单列表、权益中心与温暖橙主行动组成。移动实现必须保留“意向与权益摘要—家庭资产列表—权益中心—会员入口”结构，但不得伪造订单数、优惠券、可提现奖励、价格、支付或下载链接。现有商业意向、会员权益、报告和课程入口将以家庭范围投影/离线草稿展示；“使用权益”只导航到会员中心或相应服务，不触发扣款、核销、下载或外发。

## UI-33 家庭档案

原始基线以成员头卡、当前关注事项、四个档案入口、成长档案时间线和蓝色查看行动组成。移动实现必须保留“家庭概览—成长重点—可回看资料—过程时间线—成果入口”的结构，但不能展示儿童姓名、年龄、学校、年级、照片或诊断结论；成员信息以家庭角色和同意状态代替。成长重点仅读取家长已选择的焦点和行动过程，不自动推断孩子能力。

## UI-34 服务记录

原始基线以“我的咨询”“我的活动”“客服支持”三段内容和服务行动组成。移动实现必须保留“咨询安排—活动意向—服务支持—返回我的服务”的层级，但只展示现有服务客户投影、活动意向和家庭私有回执。顾问记录、客服、联系动作必须是说明或私有反馈草稿，不能真实拨号、发消息、创建客服工单、发送通知或伪称已经预约/报名。

## 私有小记 AI 标签边界

AI 标签能力作为无持久化的模型网关适配器存在，不承载 Family API 的家庭成长、会员、服务或档案业务状态。输入只能是已通过本地与服务器双重去标识化检查的家庭私有草稿标题、正文和用户选择话题；服务器动态选择当前可用的结构化输出模型。输出只能从受控的家庭成长标签表中返回 2 至 5 个标签，并且始终标记为“可编辑分类建议，不是事实或结论”。

模型调用失败、模型不可用、模型输出不在受控词表或输入含有可识别家庭信息时，必须安全降级到规则分类或直接阻止请求。标签不写入核心本体、报告、测评、会员、服务记录或公共社区；不会公开发布、创建评论、增加计数、发送通知或影响任何成长结果判断。

## 移动运行态核对（UI-26、UI-29 至 UI-34）

在 390×844 的移动竖屏运行态下，UI-29 保留了成果回看、过程片段与档案入口的蓝色成长层级；UI-30 保留了年度陪伴的家庭身份、快捷入口、当前陪伴与会员权益区域；UI-31 保留计划进度、支持角色与本周事项；UI-32 保留交易摘要、资产分类和权益入口；UI-33 保留家庭成员/关注事项、档案卡与成长时间线；UI-34 保留咨询活动分组、服务支持和返回服务行动。该尺寸为历史运行记录；后续布局调优统一使用 iPhone 16 Pro Max 逻辑视口 440×956。各页延续深蓝主层级、行动蓝、成长绿和温暖橙的 Warm Intelligence 表达，未出现支付、下载、导出、外联、诊断、排名或效果承诺。

UI-26 的标签入口位于话题之后、隐私提示之前，保持小记标题—正文—话题—标签—私有可见性的基线阅读顺序。空内容状态下提取按钮不可用；有内容并通过隐私识别后，可获取受控标签建议、手动加标签或删除标签。标签文案明确为“可编辑的整理建议”，不作为事实、诊断或公共发布内容。
