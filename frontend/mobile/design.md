# Family AI Mobile Design

## 1. 产品定位

Family AI Mobile 是家庭成长操作系统的 iOS/Android 入口。它不以“问 AI”为首页，而以家庭今天可以完成的一件小行动为核心，把测评、21 天成长营、90 天计划、每日任务、阶段回顾、专家服务、会员权益、社区内容和家庭档案组织成连续旅程。

产品默认面向家长，但所有涉及孩子的页面都必须尊重孩子的自主与隐私。行动完成只表示本次行动发生；家长反思属于 Perspective；系统建议属于 Recommendation；经来源确认的观察才可能成为 Fact。应用不生成家庭总分、跨家庭排名或儿童诊断。

## 2. 移动端信息架构

为符合 iOS HIG 和单手操作，底部只保留五个一级标签。当前必需交付口径是 UI-01 至 UI-34 的 34 张移动端截图基线；UI-35 已从产品基线中删除。21 天智慧父母成长营保留为业务 Program，经 UI-14 商品详情、ProgramEnrollment、UI-09 今日行动、UI-31 我的服务和 UI-34 服务记录承载。

| 一级标签 | 用户问题 | 对应页面 |
| --- | --- | --- |
| **今天** | 我们家今天最值得做什么？ | UI-01、UI-09、UI-10；21 天 Program 的每日行动进入 UI-09 |
| **成长** | 我们正在经历什么，下一步怎么走？ | UI-02~UI-08、UI-11、UI-12、UI-29 |
| **发现** | 有哪些课程、内容和家长经验适合我？ | UI-13~UI-18、UI-25~UI-28 |
| **服务** | 什么时候需要专家、咨询或活动？ | UI-19~UI-24、UI-31、UI-34 |
| **我的** | 我的会员、资产、家庭档案和记录在哪里？ | UI-06、UI-18、UI-30、UI-32、UI-33 |

一级标签标题使用用户语言，不使用“Growth OS”“Model Gateway”等工程术语。工程状态只在开发调试和系统来源说明中出现。

## 4. 六大业务循环

| 循环 | 移动端闭环 |
| --- | --- |
| 成长 | 首页 → 今日任务 → 完成/反思 → 里程碑 → 新的今日提示 |
| 计划 | 测评 → 解读 → 21 天/90 天计划 → 每日行动 → 阶段复盘 → 调整计划 |
| 评估 | 观察与家长视角 → 来源分层报告 → 人工确认 → 阶段回顾 → 新优先级 |
| 服务 | AI 陪练 → 专家列表 → 咨询需求草稿 → 服务确认 → 服务记录 → 回访 |
| 商业 | 课程/会员发现 → 意向 → Dev 内部权益激活 → 权益使用 → 资产回读 → 续费意向 |
| 社区 | 家长小记草稿 → 去标识化与可见性 → 审核 → 互动 → 私有/公开记录回读 |

## 5. 关键用户流程

### 5.1 今天完成一次家庭行动

用户打开“今天”看到今晚一件事，点击进入 UI-09，阅读原因和建议话术，选择“开始”，完成后记录行动并可选填写反思。返回首页后显示“这次行动已记录”，下一步提示明天观察一个信号。系统不显示分数，不声称孩子已改变。

### 5.2 从家庭困扰进入 21 天成长营

用户从 UI-01、UI-02 或 UI-14 选择一个高频场景，系统解释 21 天营的三个阶段、每天预计用时和非疗效边界。家庭确认后形成 ProgramEnrollment；每天只在 UI-09 突出一张行动卡，UI-31 显示服务进度，UI-34 留存服务/成长记录。Day 7、14、21 只生成过程小结，完成后提供 UI-04 的 90 天计划草稿入口，但不自动创建计划或会员。

### 5.3 从 AI 陪练升级为人工服务

用户在“问法咪莉校长”描述冲突，系统区分家长视角、可能视角和建议。普通场景给一个今晚行动；需要更多帮助时进入 UI-19/20 选择专家并在 UI-21 保存咨询需求草稿。高风险关键词直接显示人工求助和紧急资源，不继续普通陪练。

### 5.4 Dev 商业与权益闭环

用户在 UI-13/14 了解方案并提交意向，在 UI-30 明确确认年度陪伴方案。Dev 环境只进行内部权益激活，不扣款、不自动续费、不外发通知。UI-32 回读已激活权益和相关资产。

## 6. 视觉系统

移动端采用 **Warm Intelligence**。默认页面使用浅蓝白背景、深蓝文字和温暖橙行动强调；AI 解读页可局部使用深蓝科技面板，显示来源和模型状态。视觉依据来自三份核心 PPT，移动转译见 `research/three-ppt-mobile-baseline.md`。

| Token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| primary | `#2563EB` | `#60A5FA` | 主按钮、当前步骤 |
| background | `#F5F8FC` | `#0A1628` | 页面背景 |
| surface | `#FFFFFF` | `#14283C` | 内容表面 |
| foreground | `#10213E` | `#F4F8FF` | 主文字 |
| muted | `#64748B` | `#A9B7C9` | 辅助说明 |
| success | `#16866D` | `#46C7A8` | 已完成、已激活 |
| warm | `#F28C45` | `#FFB178` | 今晚行动、温暖提示 |
| stage | `#E9B949` | `#F6D675` | 阶段节点 |
| ai | `#00A8E8` | `#36C5F0` | AI 来源和系统连接 |

页面使用 iOS 习惯的 44pt 最小触控区域、清晰导航标题、原生返回手势、底部主动作和支持 Dynamic Type 的文字层级。主操作尽量位于屏幕下半部，单手即可完成；长列表使用 `FlatList`，不在页面中堆叠大量小卡片。

## 7. 品牌与图标方向

应用显示名为 **家庭成长**。图标以“家 + 生长路径 + 温暖光点”为核心，不使用机器人脸或大脑图标。视觉应既像家庭陪伴产品，又保留平台与数据连接感；图标必须填满正方形画布，不预制圆角。

最终图标使用深蓝方形背景、白色房屋与守护弧线、中央橙色家庭光点和屋顶绿色新芽。它在不依赖文字的情况下同时表达“家庭被承托”“持续成长”和“温暖智能”，与三份 PPT 的深蓝、成长绿和温暖橙视觉语言一致。首次生成的字母化构图已弃用，最终资产不含字母、网格、设计辅助线、机器人或大脑符号。

## 8. 数据与 AI 状态

移动端领域状态统一包含 `sourceType`、`evidenceBoundary`、`recommendationSource`、`modelGatewayStatus`、`visibility` 和 `updatedAt`。核心写入只通过 Named Action；模型输出只能生成解释或草稿，不能直接更改 GrowthProfile、Outcome、会员、订单或服务状态。

## 9. 测试与验收

每个页面至少验证：路由可达、加载/空/错误/成功状态、主要按钮有反馈、返回路径无死路、屏幕阅读器标签、字体放大、窄屏不截断。核心纵切额外验证 Bearer-only 家庭范围、幂等 check-in、反思不进入 Fact、Dev 商业无外部效果、21 天阶段推进和 UI-30 → UI-32 权益回读。
