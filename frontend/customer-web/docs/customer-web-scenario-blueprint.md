# AiFamily 客户 Web 业务场景重设计蓝图

## 设计结论

34 个移动端 UI 是需求证据，不是 Web 页面清单。客户 Web 采用**场景工作空间**作为页面边界：用户在同一个 Web 工作空间内完成理解、比较、确认、继续和回看，不被迫在多个小屏页面之间反复跳转。纵向沉浸内容流只用于今日行动、家庭记录和成长内容；测评、计划、服务选择、家庭档案等需要对照信息的任务使用 Web 双栏或多栏工作台。

现有移动端需求被归并为八个 Web 工作空间。每个工作空间必须同时回答三个问题：用户为什么来到这里、此刻要完成什么、完成后哪个领域状态发生变化。

| Web 工作空间 | 核心场景 | 吸收的 App UI | 主要领域对象与状态 |
|---|---|---|---|
| 成长首页 `/` | 看见今天最值得做的一件事，并进入当前流程 | UI-01、UI-31 摘要、UI-33 摘要 | Family Context、JourneyPlan、GrowthAction、服务摘要 |
| 理解家庭 `/understand` | 选择对象与边界，完成测评，审阅并确认成长假设 | UI-07、UI-02、UI-02-result、UI-03、UI-08 | AssessmentSession、Response、Evidence、GrowthHypothesis、GrowthIntent |
| 成长计划 `/journey` | 查看 90 天阶段、确认计划、暂停/恢复、进入阶段复盘 | UI-04、UI-05、UI-11、UI-31 | JourneyPlan、Phase、PhaseReview、PlanPause、GrowthAction |
| 今日行动 `/today` | 开始、暂停、继续、取消、完成行动，并留下复盘 | UI-09、UI-10 | GrowthAction、ActionState、CheckIn；孩子侧能力保持受控入口 |
| 家庭时光 `/moments` | 用文字、语音、图片或视频保存过程，形成私有故事与阶段回看 | UI-12、UI-26、UI-28、UI-29 | FamilyMomentDraft、Perspective、EvidenceRef、Milestone |
| 专业支持 `/support` | 浏览服务、比较适用场景、保存咨询/活动意向并回看安排 | UI-19、UI-20、UI-21、UI-22、UI-23、UI-24、UI-34 | ServiceOffering、AvailabilitySlot、BookingRequest、ServiceRecord、Consent |
| 家庭互助 `/community` | 浏览经审核经验、阅读观点、管理分享草稿 | UI-25、UI-27、UI-28 的公开侧、UI-15 的内容分享侧 | PrivateDraft、PublishedExperience、Visibility、ModerationState |
| 权益与家庭 `/family` | 管理成员、角色、同意、会员权益、方案意向和家庭资产 | UI-06、UI-13、UI-14、UI-15 权益侧、UI-16、UI-17、UI-18、UI-30、UI-32、UI-33 | FamilyMembership、ConsentGrant、Subscription、Benefit、OrderIntent、Asset |

## 七阶段用户流程在 Web 中的落点

| 家长阶段 | 触发场景 | Web 任务 | 完成标志 | 下一步 |
|---|---|---|---|---|
| 触发 | 孩子出现现实问题，不知道今晚怎么处理 | 首页输入文字、语音、照片或短视频，但只有主动提交才发送 | 形成本地草稿或受控 NeedSignal | 进入理解家庭 |
| 觉醒 | 想理解正在发生什么 | 完成测评并查看 GrowthHypothesis | 家长 `CONFIRM` 或 `DISMISS`，确认后才形成 GrowthIntent | 进入成长计划 |
| 行动 | 愿意先尝试一个小改变 | 在今日行动中开始、暂停、继续、取消或完成 | 幂等状态回执与可选 CheckIn | 回到首页或家庭时光 |
| 改变 | 想持续练习并看见过程 | 查看计划阶段、过程证据和阶段复盘 | 家长选择继续、调整或暂停 | 继续行动或寻找支持 |
| 支持 | 家庭需要专家或活动帮助 | 比较服务、确认同意、保存预约意向 | BookingRequest，而非服务结果 | 回看我的支持 |
| 长期 | 需要管理成员、权益和长期服务 | 管理同意、角色、权益和资产 | 可审计的家庭/会员状态 | 返回当前成长旅程 |
| 传播 | 愿意分享对其他家庭有帮助的过程 | 从私有草稿去标识化后提交审核 | ModerationState；默认不公开 | 进入家庭互助 |

## 34 个 UI 的处置矩阵

| UI | 原需求 | Web 处置 | 处置理由 |
|---|---|---|---|
| UI-01 | 家庭成长首页 | 保留核心，重构为沉浸式成长流与流程入口 | 首页承担跨流程编排，不复制移动端卡片堆栈 |
| UI-02 | 家庭测评 | 合并进“理解家庭”步骤流 | Web 需要同屏显示题目、进度、边界说明与已选答案 |
| UI-03 | AI 成长诊断 | 重命名为“成长理解”，合并进理解工作台 | 后端语义是 Hypothesis，不得呈现为诊断或事实 |
| UI-04 | 90 天成长方案 | 合并进成长计划工作台 | 计划说明、阶段与确认需要并行对照 |
| UI-05 | 90 天陪跑 | 合并进成长计划与今日行动 | 计划管理和执行属于连续流程 |
| UI-06 | 我的会员 | 合并进权益与家庭 | 权益应服务当前旅程，而非独立营销页 |
| UI-07 | 成长测评入口 | 作为理解工作台的空状态和入口，不单列页面 | 减少一次无意义跳转 |
| UI-08 | 家庭过程回顾 | 重构为过程证据，不展示成长评分 | 避免把假设和过程包装为结果事实 |
| UI-09 | 今日成长任务 | 保留为单焦点沉浸页面 | 符合“一屏一行动”的高频场景 |
| UI-10 | 孩子成长小助手 | 作为今日行动的受控“共同参与模式” | 儿童直接作答处于 HOLD，不能独立开放 |
| UI-11 | 成长榜单 | 禁止搬运，重构为“我们的成长节奏” | 永久禁止跨家庭排行与家庭评分 |
| UI-12 | 成长成果海报 | 重构为隐私友好故事卡 | 只表达过程与里程碑，不表达效果证明 |
| UI-13 | 家庭成长商城 | 重构为按问题场景发现支持 | 当前无正式 catalog，不使用消费型货架首页 |
| UI-14 | 成长方案详情 | 合并进支持/权益详情抽屉 | 保存意向，不伪装真实购买 |
| UI-15 | 邀请有礼 | 拆为内容分享与权益记录两个能力 | 分享关系与商业权益必须分离 |
| UI-16 | 家庭同行计划 | 合并进家庭互助，保留意向语义 | 无扣款与真实拼团，不使用“去拼团”误导文案 |
| UI-17 | 成长积分 | 禁止搬运硬编码余额，重构为行动纪念与权益账本 | 不展示虚构积分，不把成长转成排名 |
| UI-18 | 会员中心 | 合并进权益与家庭 | 管理状态，不构造等级崇拜 |
| UI-19 | 名师专区 | 合并进专业支持浏览区 | 以适用场景和服务边界筛选，不按人气排名 |
| UI-20 | 名师详情 | 作为支持工作台详情面板 | 列明专业背景、边界和可用时段 |
| UI-21 | 在线咨询预约 | 作为支持工作台步骤抽屉 | 必须补充取消入口和 Consent 状态 |
| UI-22 | 沙龙活动 | 合并进专业支持活动视图 | 与咨询共享家庭需要和服务记录 |
| UI-23 | 活动详情 | 作为活动详情面板 | 保存意向不等于报名或名额确认 |
| UI-24 | 我的咨询与活动 | 合并进专业支持的“我的安排” | 与浏览、预约和回看形成闭环 |
| UI-25 | 家长社区 | 重构为经审核经验流 | 不展示真实跨家庭推荐，先按审核与主题组织 |
| UI-26 | 发布家庭小记 | 合并进全局多模态记录器 | 默认私有草稿，用户另行决定是否提交审核 |
| UI-27 | 家庭小记详情 | 作为经验详情抽屉 | 区分作者视角、评论观点与可核验事实 |
| UI-28 | 我的社区 | 拆入家庭时光和家庭互助 | 私有记录与公开内容不能混为一种资产 |
| UI-29 | 成长成果 | 重构为过程回看与里程碑 | 不声称教育效果，不展示硬编码徽章事实 |
| UI-30 | 年度陪伴方案 | 合并进权益与家庭 | 当前为 Gate Boundary，仅展示可核验权益与意向 |
| UI-31 | 我的服务 | 拆为首页摘要、计划与专业支持 | “服务”包含不同领域对象，不应塞进一个列表 |
| UI-32 | 订单与资产 | 合并进权益与家庭 | 严格区分意向、已激活权益和真实资产 |
| UI-33 | 家庭档案 | 作为权益与家庭的核心工作台 | 成员、角色、同意与成长关注方向同屏管理 |
| UI-34 | 服务记录 | 合并进专业支持时间线 | 区分服务发生、顾问记录与家长反馈 |

## 前后端边界

当前可优先对齐的两个闭环是 Assessment 与 Service Booking。其他工作空间可以完成信息架构和交互，但未有生产 API 的状态必须显式标注为体验数据、只读预览或暂不可用。页面不得通过本地硬编码制造积分余额、家庭分数、孩子等级、专家人气、教育效果或已购买权益。

AI 输出只允许显示为 `Perspective`、`Recommendation` 或 `DRAFT`。家长对成长假设的确认、计划阶段变化、服务预约、会员与公开分享都必须形成可审计的 Named Action；涉及未成年人媒体、私密文字和服务需求时，界面必须在提交前显示用途、范围和同意状态。

## 依据

本蓝图以 AiFamily 的 `frontend/mobile/lib/family/ui-registry.ts`、`docs/00_system/CURRENT_PRODUCT_MAP.md`、`docs/02_business/BUSINESS_SCENARIOS_AND_PROCESSES.md`、`docs/00_system/TARGET_ARCHITECTURE.md` 与 `contracts/frontend/` 为需求依据。遇到文档与当前代码漂移时，以当前 Python 代码、运行时契约与 fail-closed 边界为准。
