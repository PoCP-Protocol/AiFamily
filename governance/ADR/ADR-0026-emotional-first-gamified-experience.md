# ADR-0026：情绪价值优先的游戏化家庭成长体验

- 状态：PROPOSED
- 日期：2026-08-30
- 决策人：chief-architect
- 关联：`docs/00_system/ARCHITECTURE_BENCHMARK_REVIEW_V3.md`

## 背景

核心商业蓝图要求同时完成家庭成长、商业增长和 FGCN 资源协作。产品体验希望借鉴抖音
在内容发现、反馈速度、连续体验和传播上的成熟机制，并使用游戏感降低家庭开始行动的门槛。
但 Family 服务家庭和未成年人，不能把注意力时长、情绪脆弱或孩子行为直接转换为商业画像。

## 决策

1. 产品价值顺序固定为：被看见/被理解 → 小胜利 → 连续成长 → 主动服务需要 → 经济选择。
2. 增加跨域 `Experience & Trust` 能力面，负责内容发现、推荐解释、节奏、暂停、反馈和
   商业闸门；不新增一个拥有家庭事实的业务域。
3. 游戏化只使用章节、任务、选择、可选徽章、家庭故事和非比较性奖励；禁止家庭总分、
   家庭排名、孩子比较、随机奖赏、倒计时惩罚和未成年人消费激励。
4. 推荐必须记录原因、版本、目的、租户、区域、语言和退出方式；允许跳过、降频、暂停、
   清空和撤回分享。
5. E0-E2（情绪承接和成长反馈）未形成有效证据时，商业能力只能被动查询；E3 之后仍须
   家长或授权主体确认，AI 不支付、不升级权益、不自动续费。
6. `experience_curator` 作为 Principal 的受治理 profile 进入 Registry；它只能返回
   Recommendation、EmotionalResponse、ActionProposal 或 HumanTask，不能直接修改事实。

## 取舍

- 采用顺滑内容发现和短反馈，可降低首次价值时间；代价是必须建设频控、暂停、解释和退出，
  不能用停留时长作为唯一优化指标。
- 采用章节和进度感，可提高 21/90 天连续性；代价是不能使用跨家庭排行榜等简单激励。
- 延迟商业入口，可降低短期转化；换取更高的信任、投诉可控性和长期复购质量。

## 后果与验收

- 业务、流程、数据、应用和 AI 五层必须引用 `P0` 体验闭环和 E0-E4 闸门。
- 34 UI 保持基线，通过投影、反馈和状态驱动，不在前端硬编码“已完成”或“已诊断”。
- dev/test/prod 使用相同推荐、游戏化、商业闸门、人工闸门、删除和错误码；测试只替换合成
  数据与适配器。
- 在 `experience_curator` 的 Registry、schema、知识范围、安全集、租户/语言契约和回归测试
  完成前，不进入实现或对外宣称上线。
